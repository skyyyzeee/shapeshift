# Файлы UUP выбираются по CompDB, кэш — по SHA-1

Выпуск UUP — около 17 000 файлов (~94 ГБ) на все языки и редакции. Какие из них нужны для языка и редакций, движок решает сам, по описаниям CompDB из `<UpdateId>.AggregatedMetadata.cab` (это первый скачиваемый файл, несколько МБ):

- для каждой пары «редакция + язык» есть свой CompDB (`DesktopTargetCompDB_professional_ru-ru`) со списком пакетов; файл пакета находится по SHA-256 из CompDB;
- встроенные приложения — из `DesktopTargetCompDB_App_Neutral`: те, что CompDB редакции называет предустановленными, со всеми обязательными зависимостями; языковые ресурсы — только для выбранного языка;
- обновления (накопительное, пакет включения версии, обновления установщика и среды восстановления) — по именам файлов; из пары `.cab` + `.msu` берётся `.cab`, разностные части (`-baseless`, `-express`, `.psf`) не нужны.

Скачанное хранится в `<рабочая папка>\cache\uup\files\<SHA-1>`: одинаковые файлы разных выпусков и редакций скачиваются один раз. Недокачанный файл лежит рядом как `.part` и докачивается с того же места (HTTP Range). Каждый файл проверяется по SHA-1 и SHA-256 из Windows Update.

## Considered Options

- Готовые списки «пакетов» с сервера uupdump.net — так делает сам UUP dump. Отклонено: зависимость от стороннего сайта (ADR-0001).
- Скачивать все файлы языка (без разбора по редакциям). Отклонено: в разы больше, а состав приложений и пакетов редакций всё равно нужен для сборки.

## Consequences

- Выпуск — это базовая сборка плюс обновления: 25H2 из UUP = 26100.1 + накопительное обновление + пакет включения. Сборка образа из UUP обязательно применяет обновления (DISM).
- Ссылки на файлы временные (несколько часов); при ответе 403/404/410 движок получает их заново — одним запросом на всё скачивание.
- Для распаковки CAB используется системный `expand.exe` (в тестах CAB собираются системным `makecab.exe`).
