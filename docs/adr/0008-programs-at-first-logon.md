# Программы ставит сценарий при первом входе, установщики лежат в sources\$OEM$

Программы профиля ставятся не в образ, а в установленную систему при первом входе. Движок кладёт на носитель папку `sources\$OEM$\$$\Setup\Shapeshift\`. В ней сценарий PowerShell `install-programs.ps1` и свои установщики (`Programs\01…`). Windows Setup переносит эту папку в `%WINDIR%\Setup\Shapeshift`, а команда первого входа из файла ответов запускает сценарий. Пакеты winget скачивает тот же сценарий, если есть интернет; без него они пропускаются с записью в журнал. Так программам не нужны ни DISM, ни права администратора при сборке, а установщик работает в настоящей системе — как при ручной установке.

## Considered Options

- Установка в смонтированный образ (офлайн). Отклонено: большинство установщиков (.exe, Office, 1С) не умеют ставиться в офлайн-образ; это работает только для appx/msix и частично для MSI.
- `SetupComplete.cmd` от имени SYSTEM до входа. Отклонено для версии 1: winget у SYSTEM без пользователя не работает, многие программы ставятся в профиль пользователя, а при OEM-ключах некоторых редакций Windows не запускает SetupComplete.
- Скачивать пакеты winget при сборке и ставить их офлайн. Отложено: нужен разбор манифестов winget и зависимостей. Пока — онлайн при первом входе.

## Consequences

- Команда первого входа выполняется до выхода из сеанса ради смены пароля, поэтому программы ставятся в том же сеансе. Сеанс пользователя-администратора идёт с полными правами, так что работают и установщики для всех пользователей (MSI, HKLM).
- Сбой одной программы не останавливает остальные; на каждую — не больше 30 минут. Журнал — `%WINDIR%\Setup\Shapeshift\programs.log`; после установки установщики удаляются.
- Сценарий записан в UTF-8 с BOM: без него Windows PowerShell 5.1 читает файл в ANSI.
- `answerfile` без сборки добавляет команду, но установщиков не несёт — и предупреждает об этом.
- Если `removeApps` удаляет App Installer (`Microsoft.DesktopAppInstaller`), пакеты winget будут пропущены — движок предупреждает.
