# Два механизма изменений, скрытых за твиками

Изменения вносятся двумя способами: через файл ответов (действует при установке и первом входе) и через офлайн-обслуживание (меняет Windows внутри образа). Где возможно, используется файл ответов — он быстрый, не требует монтирования и не может испортить образ; офлайн-обслуживание — только для того, что иначе невозможно (языковые пакеты, редакции, обновления, драйверы, .NET 3.5, встроенные приложения). Пользователь видит единый список твиков, механизм определяется этапом каждого действия в каталоге.

## Consequences

- Набор твиков, не требующих офлайн-обслуживания, даёт «лёгкую» сборку за секунды и экспорт одного файла ответов для обычного ISO.
- Обход ограничений, создание пользователя и большинство твиков реестра принципиально живут в файле ответов, а не в образе — не «исправлять» это переносом в офлайн-реестр без причины.
