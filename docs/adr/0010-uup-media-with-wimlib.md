# Носитель из UUP собирается wimlib, без DISM

Образ редакции из UUP (`professional_ru-ru.esd`) содержит три образа: файлы установщика, среду восстановления (WinPE) и саму Windows. Данные Windows в нём не лежат — образ ссылается на них по SHA-1, а сами данные — в пакетах выпуска: часть в ESD/WIM, часть в CAB. Движок собирает носитель только wimlib:

- образ 1 разворачивается в папку носителя;
- образ 3 экспортируется в `sources\install.wim` со ссылками на пакеты; CAB-пакеты перед этим распаковываются (`expand.exe`) и упаковываются во временные WIM — данные с тем же SHA-1 находятся по ссылкам; следующие редакции экспортируются в тот же WIM, общие данные хранятся один раз;
- образ 2 становится `Winre.wim` внутри каждой редакции и основой `sources\boot.wim`: образ 1 — Windows PE, образ 2 — установщик (`setup.exe` и файлы `sources`, без `winpeshl.ini`, загрузочный).

Так сборка из UUP не требует прав администратора и работает на любом хосте, в том числе там, где DISM не может открыть образ.

## Considered Options

- Применить образ на диск DISM и захватить заново. Отклонено: медленно, нужны права администратора и рабочий DISM хоста.
- Скачать готовый ESD от Microsoft (каталог Media Creation Tool). Отложено: только для текущих выпусков и без выбора состава; UUP даёт и Insider, и языковые пакеты (ADR-0001).

## Consequences

- Без встроенных приложений и обновлений результат — исходная сборка версии (например, 26100.1 для 24H2 и 25H2). Приложения из выпуска добавляются при офлайн-обслуживании (DISM, задача 20/21), обновления — задача 22.
- В образе 1 `boot.wim` не правится реестр (`InstRoot`, как делает uup-converter) — установщик загружается из образа 2, ему это не нужно.
