# 14: Встроенные приложения

**What to build:** На шаге «Настройка» пользователь видит список встроенных приложений, прочитанный из самого образа. У известных каталогу — понятное название и пометка «безопасно / может сломать», у неизвестных — техническое имя и пометка «неизвестно». Кнопка «рекомендованные» выбирает рекомендованные к удалению. Выбранные приложения удаляются из образа офлайн. Список приложений читается из образа, разметка — из каталога (ADR-0004). Сценарии спецификации: 36–39.

**Blocked by:** 10, 13

**Дополнительно из 13:** монтирование образа через DISM API (управляемая обёртка `Microsoft.Dism`) с прогрессом в канале; автоочистка зависших монтирований при старте движка и команда `cleanup`; отмена во время монтирования — монтирование отключается без сохранения, исходный образ не тронут; проверка версии DISM хоста относительно выпуска (предупреждение и путь к DISM из ADK). Тесты с монтированием требуют прав администратора — отдельная категория.

## Заметки

- `apps list --iso <ISO> [--edition <id>] [--json]` — без прав администратора: ISO подключается через `Mount-DiskImage`, `install.wim` читается wimlib (папки `Program Files\WindowsApps`; фреймворки — по `<Framework>` в манифесте, ресурсные `split.*` пропускаются).
- Удаление — шаг сборки `RemoveApps`: ESD сначала превращается в WIM (DISM не монтирует сплошное сжатие), затем каждая редакция монтируется, из неё удаляются provisioned-пакеты (по `DisplayName`), образ сохраняется. Нужны права администратора (код выхода 5 без них). При ошибке или отмене образ отключается без сохранения; отмена не прерывает само отключение.
- Каждое монтирование помечается файлом `.shapeshift-mount` в папке сборки; перед сборкой и в `cleanup` такие зависшие монтирования отключаются без сохранения, чужие не трогаются.
- Admin-тесты (`Category=Admin`): удаление на настоящем образе, отмена во время монтирования и после удаления, очистка зависшего монтирования — 4/4 в ВМ стенда (`tools/bench/Invoke-AdminTestsInVm.ps1`).
- На хосте разработки (Windows Insider 26300) DISM не может открыть ни один смонтированный образ: не загружаются кусты реестра (`reg load` падает даже на только что сохранённом кусте, ошибка 206), DISM — ошибка 87, «Failed trying to determine the OS Version». Движок сообщает об этом понятной ошибкой. Остальные admin-тесты на хосте проходят.
- Стенд «у нового пользователя удалённых приложений нет» не проверен: образ с удалением нельзя собрать на этом хосте. Тест на настоящем образе проверяет, что папок удалённых пакетов в результате нет.
- Окно: карточка «Встроенные приложения» на шаге «Настройка» (в обычном режиме — только safe, в продвинутом — все), выбор в профиле (`removeApps`) и в сводке. Вживую окно не проверялось.
