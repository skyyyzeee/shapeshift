# 02: Пользователь и OOBE в файле ответов

**What to build:** Пользователь задаёт в профиле локального пользователя и параметры установки, и `answerfile` выдаёт файл ответов, с которым установка проходит без участия: создаётся локальная учётная запись, аккаунт Microsoft и интернет не требуются, экраны OOBE пропускаются, компьютер получает заданное имя. Пароль по умолчанию требуется сменить при первом входе; режим «хранить пароль» включается явно. Авторазметка диска (стирает диск 0) поддерживается, но по умолчанию выключена — она нужна стенду Hyper-V (05). Сценарии спецификации: 25–33.

## Comments

**Сделано (2026-10-20).** Раздел профиля `setup`: `user` (`name`, `password.mode` = `changeAtFirstLogon` | `store`, `password.value`, `autoLogon`), `computerName`, `skipOobe`, `bypassOnlineAccount`, `wipeDisk0`.

Решения по ходу:

- **Смена пароля при первом входе** сделана через первый вход, а не через `SetupComplete.cmd`: учётная запись создаётся с пустым паролем, при первом входе выставляется флаг «сменить пароль» и сеанс сразу завершается — экран входа просит задать пароль. `SetupComplete.cmd` на устройствах с OEM-ключом может не выполняться.
- **Автовход разрешён только с режимом `store`** — с паролем, который нужно сменить, он работать не может; профиль с таким сочетанием отклоняется.
- **Хранимый пароль** записывается в стандартной для файлов ответов форме base64 (как «скрыть конфиденциальные данные» в Windows SIM) — от случайного взгляда, не шифрование. Движок пишет предупреждение; второе предупреждение — при `wipeDisk0`.
- **Разметка диска 0** — по образцу Microsoft для UEFI/GPT: WinRE 1 ГБ, EFI 300 МБ, MSR, Windows на остаток; установка в раздел 4.
- **«Пропуск OOBE»** скрывает лицензию, регистрацию OEM и экран конфиденциальности (`ProtectYourPC` = 3, без отправки дополнительных данных). Регион и раскладки по-прежнему спрашиваются — это задача 03.
- **Правила имён** вынесены в `NameRules` (Core), чтобы окно (09) использовало те же проверки для подсказок у полей.
- **Схема в тестах стала строгой**: необъявленный элемент (в том числе опечатка в генераторе) делает файл недействительным.

Проверить на стенде Hyper-V (05): группа `Administrators` на русской Windows, сценарий смены пароля, `BypassNRO` без сети.

**Проверено стендом Hyper-V (2026-10-20)**, Windows 11 24H2 26100.9168, сценарий `full-unattended`: установка без участия на ВМ без TPM и без сети, пользователь — администратор (группа `Administrators` на русской Windows работает), имя компьютера, редакция Pro выбрана по номеру без страницы ключа, форматы ru-RU, раскладки en-US → ru-RU, часовой пояс.
