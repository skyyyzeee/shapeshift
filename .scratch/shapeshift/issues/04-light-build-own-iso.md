# 04: «Лёгкая» сборка своего ISO

**What to build:** Пользователь запускает `build --profile <file>`, указав в профиле свой ISO, и получает новый ISO с файлом ответов внутри, загружающийся и на BIOS, и на UEFI. Движок читает из ISO выпуск, архитектуру и редакции (неподходящий образ отклоняется с понятной ошибкой), проверяет свободное место в рабочей папке, распаковывает образ, кладёт файл ответов и упаковывает ISO через IMAPI2 (ADR-0006). Офлайн-обслуживания нет — права администратора не нужны. `build --dry-run` выводит план шагов и оценку места, ничего не делая. Сценарии спецификации: 1, 3, 4, 50, 55, 56, 60.

## Comments

**Сделано (2026-10-19).** Команды `inspect --iso` и `build --profile [--workspace] [--dry-run]`. Сборка из настоящего Windows 11 24H2 (26100.9168, 8 ГБ) занимает около минуты: распаковка → файл ответов → ISO 8,5 ГБ.

Решения по ходу:

- **Метаданные WIM читаются напрямую из заголовка**, без wimlib: XML лежит несжатым и в WIM, и в ESD, формат документирован. wimlib по-прежнему нужен для экспорта и сжатия (задача 13).
- **ISO читается через DiscUtils** (LTRData.DiscUtils, MIT) — без монтирования и прав администратора.
- **Результат — только UDF** (без моста ISO 9660, как в официальных образах). Загрузка через El Torito от файловой системы не зависит, установщик читает UDF. Реальную загрузку проверит стенд Hyper-V (05).
- **UEFI-загрузчик — `efisys.bin` (с запросом «Press any key»)**, а не `efisys_noprompt.bin`: иначе после перезагрузки установка начнётся заново, если образ остался подключён. Стенду (05) нужно будет нажимать клавишу или менять порядок загрузки.
- **IMAPI держит файлы дерева, пока живы его COM-объекты** — без явного освобождения папка сборки не удалялась (поймано на настоящем образе). Также IMAPI сбоит при параллельной работе в одном процессе — упаковки сериализованы.
- **Профиль v1 дополнен** необязательными `source.iso` и `output.iso`; относительные пути разрешаются от папки профиля. Рабочая папка по умолчанию — `%LOCALAPPDATA%\Shapeshift\Workspace` (выбор диска с наибольшим свободным местом — в окне, задача 12).
- **IMAPI не умеет пути длиннее MAX_PATH (259).** Самый длинный путь в образе Windows 11 — 147 символов, поэтому папки сборки названы коротко, а до распаковки проверяется, что самый длинный путь влезет; иначе — понятная ошибка с допустимой длиной рабочей папки (поймано тестом на настоящем образе).
- **Код выхода 3** — не хватает места (проверка до начала распаковки).
- **Тесты**: быстрые — на синтетическом ISO со структурой установочного образа (собирается в тесте); медленные — на настоящем образе, включаются переменной `SHAPESHIFT_TEST_ISO`.
