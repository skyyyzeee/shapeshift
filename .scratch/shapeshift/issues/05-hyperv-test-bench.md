# 05: Стенд Hyper-V для сквозной проверки

**What to build:** Разработчик одной командой проверяет, что результат `build` действительно ставится без участия человека и делает то, что обещано. Стенд создаёт ВМ Hyper-V (поколение 2, без TPM — чтобы проверить обход), загружает её с результата, ждёт окончания автоматической установки и через PowerShell Direct проверяет установленную систему, после чего удаляет ВМ. Это не новый шов, а глубокая проверка результата того же CLI. Сценарий спецификации: 83.

## Comments

**Сделано (2026-10-20).** `tools/bench/Invoke-Bench.ps1` + сценарий `full-unattended`. Первый прогон на Windows 11 24H2 (26100.9168): **PASSED**, 7 из 7 проверок, сборка ~1 мин + установка ~6 мин, ВМ и файлы удалены.

Решения по ходу:

- **Сценарий = профиль + `expect.json`**; новые проверки добавляются в блок `switch` скрипта.
- **«Press any key»** — стенд первые 60 с нажимает Enter через WMI (`Msvm_Keyboard`); порядок загрузки «диск, потом DVD» — чтобы после перезагрузки не начать установку заново.
- **Готовность** — PowerShell Direct отвечает под пользователем профиля и Проводник запущен в интерактивном сеансе (автовход завершён). Культура читается из реестра пользователя: `Get-Culture` в удалённом сеансе отдаёт культуру хоста.
- **Рабочая папка — `.bench\` в репозитории, не `%LOCALAPPDATA%`**: при запуске из упакованного (MSIX) приложения, например Claude, запись в `%LOCALAPPDATA%` перенаправляется в папку пакета, и служба Hyper-V файлов не видит (поймано на первом прогоне).
- **Таймаут** — снимок экрана ВМ (`timeout.png`), плюс `progress.png` каждые 2 минуты.

Не проверено стендом: сценарий смены пароля при первом входе (`changeAtFirstLogon`) — PowerShell Direct не войдёт под пустым паролем; нужен отдельный сценарий с проверкой по снимку экрана.
