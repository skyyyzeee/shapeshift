# 03: Регион и ключ установки в файле ответов

**What to build:** Пользователь задаёт в профиле регион — форматы, раскладки клавиатуры, часовой пояс — независимо от языка интерфейса, и редакцию с ключом установки. `answerfile` выдаёт файл ответов, где регион применён, установщик не спрашивает ключ (используется общедоступный ключ установки выбранной редакции), а если пользователь вписал свой ключ — используется он. Средств активации нет (ADR-0007). Сценарии спецификации: 19, 20, 34, 35.

## Comments

**Сделано (2026-10-20).** Раздел профиля `regional` (`formats`, `keyboards` — первая по умолчанию, `timeZone`), `setup.edition`, `setup.productKey`; у `answerfile` появился `--iso` (по умолчанию — `source.iso` профиля).

Отступления от плана:

- **Без ключей установки.** Редакция выбирается номером в образе (`InstallFrom` → `/IMAGE/INDEX`) с нулевым ключом и `WillShowUI=Never` — установщик не спрашивает ключ, программа не хранит ни одного ключа. ADR-0007 и сценарий 34 спецификации обновлены. Пункты задачи про ключ установки для каждой редакции и «неизвестная редакция — ошибка» выполнены в этой форме: редакции, которой нет в образе, — ошибка со списком доступных.
- **Язык установщика берётся из образа** (язык по умолчанию из метаданных WIM). Без него первый экран установщика не пропустить, а язык, которого нет в образе, указывать нельзя. Поэтому без `--iso` экран языка остаётся, движок об этом предупреждает.
- **Пропуск OOBE теперь принимает лицензию и в установщике** (`AcceptEula`), а не только в OOBE.

Проверить на стенде Hyper-V (05): выбор редакции по номеру с нулевым ключом на 24H2 действительно не показывает страницу ключа. Если покажет — запасной вариант: `WillShowUI=OnError` либо выбор по `/IMAGE/NAME`.
