# Shapeshift — спецификация

## Problem Statement

Подготовить установочный образ Windows «под себя» сегодня — это зоопарк инструментов и ручной работы. Образ скачивается одним средством (Rufus/Fido — причём с российских IP официальная загрузка заблокирована, — или uupdump.net), языки добавляются через DISM вручную или NTLite/MSMG, обход TPM и автосоздание пользователя — через самописный `autounattend.xml` по статьям из интернета, твики — скриптами после установки, запись на флешку — снова Rufus. Каждый шаг требует знать, какой механизм за ним стоит, ошибка в файле ответов обнаруживается только после 15 минут установки, а повторить ту же подготовку через месяц для нового выпуска приходится с нуля.

## Solution

Shapeshift — одна программа на WinUI 3 с минималистичным мастером из пяти шагов: **Источник → Редакции и языки → Установка → Настройка → Результат**. Пользователь выбирает свой ISO или скачивает любой выпуск Windows 10/11 через UUP, выбирает редакции, языки интерфейса и регион, включает обход ограничений, локального пользователя и твики, и получает готовый ISO, ISO на флешке Ventoy или загрузочную флешку. Программа сама решает, что сделать через файл ответов, а что через офлайн-обслуживание. Все выборы сохраняются в профиль, который можно повторить на новом выпуске. Продвинутый режим раскрывает дополнительные выборы на тех же шагах. Сборка выполняется движком — отдельной программой без интерфейса, которую можно запускать и из командной строки.

## User Stories

### Источник

1. Как пользователь, я хочу выбрать свой ISO через диалог, чтобы подготовить образ, который у меня уже есть.
2. Как пользователь, я хочу перетащить ISO из Проводника в окно, чтобы не искать файл через диалог.
3. Как пользователь, я хочу, чтобы после выбора ISO программа показала выпуск, архитектуру и список редакций внутри, чтобы убедиться, что это нужный образ.
4. Как пользователь, я хочу получить понятную ошибку, если файл не является установочным образом Windows или его выпуск не поддерживается, чтобы не ждать падения в середине сборки.
5. Как пользователь, я хочу скачать Windows через UUP, выбрав версию, выпуск, язык и редакции, чтобы не искать образ на сторонних сайтах.
6. Как пользователь из России, я хочу, чтобы скачивание работало без VPN, чтобы не упираться в блокировку официальной страницы Microsoft.
7. Как пользователь, я хочу видеть по умолчанию только выпуски каналов Retail и Release Preview, чтобы случайно не взять нестабильную сборку.
8. Как опытный пользователь, я хочу в продвинутом режиме видеть выпуски Insider (Beta, Dev, Canary) с предупреждением, что твики могут не работать, чтобы собирать тестовые образы.
9. Как пользователь, я хочу использовать официальную страницу Microsoft как запасной источник, чтобы скачать образ, если UUP временно недоступен.
10. Как пользователь, я хочу видеть прогресс, скорость и оставшееся время скачивания, чтобы понимать, сколько ждать.
11. Как пользователь, я хочу, чтобы прерванное скачивание продолжилось с места остановки, чтобы не качать гигабайты заново.
12. Как пользователь, я хочу, чтобы скачанные файлы проверялись по хешам, чтобы не собрать образ из повреждённых данных.
13. Как пользователь, я хочу использовать образ Enterprise LTSC как свой ISO, чтобы готовить LTSC-системы (через UUP LTSC недоступен).

### Редакции и языки

14. Как пользователь, я хочу выбрать, какие редакции оставить в образе, чтобы уменьшить его размер и не выбирать редакцию при установке.
15. Как пользователь UUP, я хочу получить редакции, которые получаются конвертацией (Education, Enterprise, Pro for Workstations), чтобы не ограничиваться Home и Pro.
16. Как пользователь, я хочу добавить в образ один или несколько языков интерфейса, чтобы установленная система сразу была на нужном языке.
17. Как пользователь, я хочу, чтобы языковые пакеты и компоненты по требованию для выбранных языков скачивались автоматически под точный выпуск образа, чтобы не искать их самому.
18. Как пользователь, я хочу выбрать язык интерфейса по умолчанию среди добавленных, чтобы система стартовала на нём.
19. Как пользователь, я хочу задать регион: форматы, раскладки клавиатуры и часовой пояс, чтобы не настраивать их после установки.
20. Как пользователь, я хочу иметь, например, русский интерфейс с английской раскладкой по умолчанию, чтобы язык и раскладки задавались независимо.

22. Как пользователь, я хочу встроить последнее накопительное обновление в образ, чтобы система была актуальной сразу после установки.

## Implementation Decisions

### Стек и упаковка

- .NET (актуальная LTS), WinUI 3 на Windows App SDK (актуальная стабильная), C#.
- Без MSIX: обычное приложение, self-contained (рантаймы внутри), распространяется как portable zip; позже — winget (`skyze.Shapeshift`).
- Хост: Windows 10 22H2 и Windows 11, x64.
- Лицензия MIT. wimlib — LGPLv3/GPLv3, подключается только как отдельная динамически загружаемая DLL (ADR-0006).
- Строки интерфейса — в ресурсах с первого дня; языки RU и EN, архитектура готова к сторонним переводам.

### Модули

- **Модель предметной области.** Типы из глоссария: Образ, Выпуск, Канал, Редакция, Архитектура, Твик, Действие, Этап, Профиль, Результат и т. д. Без зависимостей от Windows API; общая для интерфейса и движка. Архитектура — поле модели с самого начала, хотя поддерживается только x64.
- **Каталог.** Загрузка, проверка подписи, валидация и запросы к каталогу: какие твики применимы к выпуску, какие конфликтуют, как разметить встроенное приложение. Формат — JSON со схемой. Типы действий (фиксированный набор в движке): значение реестра (с указанием куста и этапа), удаление встроенного приложения, включение/отключение компонента, команда на этапе установки или первого входа. Каждое действие несёт этап: в образе / во время установки / при первом входе.
- **Генератор файла ответов.** Чистая функция: профиль + каталог + выпуск → файл ответов и сопровождающие скрипты (`SetupComplete`, `FirstLogon`). Покрывает обход ограничений, пользователя и пароль (по умолчанию — смена при первом входе), автовход, OOBE, имя компьютера, регион, разметку диска (только при явном включении), ключ установки, действия твиков на этапах установки и первого входа. Без файлового ввода-вывода внутри.
- **Планировщик сборки.** Превращает профиль в упорядоченный план шагов сборки и решает, нужно ли офлайн-обслуживание вообще (если нет — сборка «лёгкая»: распаковать → положить файл ответов → упаковать). Оценивает требуемое место.
- **Офлайн-обслуживание.** Монтирование образа и операции над ним через управляемую обёртку DISM API (`Microsoft.Dism`): удаление редакций, языковые пакеты и компоненты по требованию, накопительное обновление, .NET 3.5, драйверы (накопители и сеть — также в `boot.wim`), удаление встроенных приложений, офлайн-реестр. Чтение списка встроенных приложений из образа. Очистка зависших монтирований при старте. Проверка версии DISM хоста относительно выпуска; при несовпадении — предупреждение и путь к DISM из ADK.
- **WIM-операции.** Через wimlib: экспорт и сжатие, ESD → WIM, разбиение на `.swm`.
- **UUP-клиент.** Прямое обращение к Windows Update: список выпусков по каналам, получение файлов для выпуска/языка/редакции, языковых пакетов, компонентов по требованию и накопительного обновления; докачка, проверка хешей, кэш. Сборка образа из файлов UUP, включая конвертацию редакций. Самый объёмный и рискованный модуль — отдельный срез.
- **Официальная загрузка.** Запасной источник через механизм страницы загрузки Microsoft.
- **Упаковщик ISO.** Через IMAPI2: UDF, загрузка BIOS + UEFI. Запасной вариант — `oscdimg`, если ADK установлен.
- **Запись носителя.** Определение флешки Ventoy и копирование ISO на неё. Отдельная флешка: GPT, один раздел FAT32, `install.wim` > 4 ГБ разбивается на `.swm` (ADR-0005). Обязательное подтверждение с названием и размером накопителя.
- **Движок (CLI).** Отдельная консольная программа (ADR-0003). Команды (имена — ориентир): `build --profile <file>` (с `--dry-run` — только план и оценка места), `answerfile --profile <file> --out <path>`, `catalog validate <file>`, `cleanup`. Это единственный шов тестирования, поэтому всё, что нужно проверить, должно быть доступно через команды. Работает с правами администратора; без интерфейса пишет прогресс и лог в консоль.
- **Протокол канала.** Интерфейс запускает движок с повышением при старте сборки и общается по именованному каналу сообщениями JSON: начало/конец этапа, прогресс, строка лога, предупреждение, ошибка, результат; от интерфейса — отмена. Отмена гарантирует отключение монтирований без сохранения и нетронутый исходный образ.
- **Интерфейс (WinUI).** Обычный процесс без повышения. Мастер из 5 шагов (Источник → Редакции и языки → Установка → Настройка → Результат), переключатель продвинутого режима раскрывает дополнительные выборы на тех же шагах. Mica, системная тема, минимум цвета. Экран твиков строится по каталогу. Сводка перед сборкой, экран прогресса с логом. Профили: сохранение, загрузка, пресеты, экспорт файла ответов. Настройки: рабочая папка, кэш, язык интерфейса.
- **Обновления.** Проверка новых версий программы и каталога через GitHub Releases; только уведомление. Никакой телеметрии.

### Профиль

- JSON, версионированный (поле версии формата), ссылается на твики по идентификаторам каталога. Содержит: источник (путь или параметры UUP), редакции, языки и регион, параметры установки, выбранные твики и приложения для удаления, драйверы, результат. Пароль хранится только если пользователь явно выбрал этот режим.
- При загрузке профиля для другого выпуска — отчёт о неприменимых твиках.

### Рабочая папка и кэш

- Рабочая папка по умолчанию — на диске с наибольшим свободным местом, выбирается в настройках. Проверка свободного места перед сборкой по оценке планировщика (ориентир 20–40 ГБ для сборки с офлайн-обслуживанием).
- Кэш UUP, языковых пакетов и обновлений хранится между сборками; размер и очистка — в настройках.

### Границы

- Средств активации и встроенных ключей нет — редакция выбирается по номеру в образе, есть поле для своего ключа (ADR-0007).
- Удаление Edge и отключение Defender в первой версии не поддерживаются.

### Порядок срезов

1. Движок CLI: свой ISO → файл ответов (обход ограничений, пользователь, OOBE, регион) → ISO. Плюс стенд проверки в Hyper-V.
2. Интерфейс WinUI: мастер, профили и пресеты, экспорт файла ответов, протокол канала.
3. Офлайн-обслуживание: редакции, встроенные приложения, офлайн-реестр, драйверы, .NET 3.5; каталог твиков целиком.
4. UUP: скачивание, сборка образа, конвертация редакций, накопительное обновление; официальная загрузка как запасной источник.
5. Языки: языковые пакеты и компоненты по требованию.
6. Носители: Ventoy и отдельная флешка.

## Testing Decisions

- Хороший тест проверяет внешнее поведение через самый высокий доступный шов — что получилось на выходе, — а не внутренние шаги.
- **Шов один — команды CLI движка.** Генератор файла ответов, каталог, планировщик, офлайн-обслуживание и протокол канала отдельных тестов не имеют: всё проверяется через команды движка, поэтому внутренние модули можно перестраивать, не трогая тесты. Быстрые тесты вызывают точку входа CLI внутри тестового процесса (без запуска отдельного процесса); шов тот же.
- Тесты разделены на уровни по стоимости, все через тот же шов:
  - **Быстрые** (без образа и прав администратора):
    - `answerfile --profile` → проверка XML по схеме файла ответов и снимки (snapshot) для набора характерных профилей;
    - `catalog validate` по поставляемому каталогу → схема, ссылки на конфликты, применимые выпуски, переводы RU/EN, уникальность идентификаторов;
    - `build --dry-run` → план шагов (в частности, «лёгкая» сборка без офлайн-обслуживания) и оценка места.
  - **С образом**: `build` на небольшом реальном ISO из кэша разработчика → проверка содержимого результата (файл ответов на месте, образ загрузочный).
  - **С офлайн-обслуживанием** (права администратора, отдельная категория): `build` → набор редакций, языковые пакеты, отсутствие удалённых приложений, значения офлайн-реестра, драйверы в `boot.wim`.
  - **Протокол канала**: тот же `build` с выводом в режиме канала → последовательность сообщений, отмена (монтирования отключены, исходный образ не тронут).
  - **Сквозная проверка в Hyper-V** (стенд разработчика, медленно, вручную или по расписанию): результат `build` устанавливается в ВМ, после автоматической установки через PowerShell Direct проверяются пользователь, значения реестра, удалённые приложения, язык интерфейса и регион. Это не новый шов, а более глубокая проверка результата того же шва.
- Интерфейс WinUI автотестами в первой версии не покрывается — вся логика живёт ниже шва движка и модели.
- Предыдущих тестов нет — репозиторий новый.
