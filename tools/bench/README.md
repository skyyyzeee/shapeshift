# Стенд Hyper-V

Сквозная проверка: результат `build` устанавливается в одноразовую ВМ без участия человека, и в установленной системе проверяется, что профиль сработал. Не входит в обычный `dotnet test` — запускается вручную или по расписанию.

## Требования

- Hyper-V включён (Windows Pro/Enterprise/Education).
- Пользователь в группе «Администраторы Hyper-V» (после добавления — выйти и войти снова) или запуск от администратора.
- Настоящий ISO Windows 10/11 x64 и ~80 ГБ свободного места на диске с репозиторием (образ, распаковка, диск ВМ). Рабочая папка — `.bench` в репозитории или `-WorkRoot`; не `%LOCALAPPDATA%`: у упакованных (MSIX) приложений, например при запуске из Claude, запись туда перенаправляется, и Hyper-V файлов не видит.

## Запуск

```powershell
.\tools\bench\Invoke-Bench.ps1 -Iso D:\win11.iso
```

или с `SHAPESHIFT_TEST_ISO`. Параметры: `-Scenario` (папка в `scenarios\`, по умолчанию `full-unattended`), `-TimeoutMinutes` (по умолчанию 60), `-KeepVm` (не удалять ВМ, диск и образ).

Код выхода 0 — все проверки прошли. При неудаче в `.bench\<прогон>` (или в `-WorkRoot`) остаются `bench.log`, `progress.png` (последний снимок экрана) и `timeout.png`.

## Как устроено

- ВМ поколения 2 с Secure Boot, **без vTPM** (установка Windows 11 проходит только благодаря обходу ограничений) и **без сети** (проверка установки без аккаунта Microsoft).
- Загрузчик образа просит нажать клавишу — стенд первые 60 секунд нажимает Enter через WMI. Порядок загрузки «диск, потом DVD», поэтому после перезагрузки установка продолжается с диска.
- Готовность — PowerShell Direct отвечает под пользователем из профиля и в его сеансе запущен Проводник (автовход).

## Admin-тесты в ВМ

Тесты с офлайн-обслуживанием DISM (`Category=Admin`) требуют прав администратора и рабочего DISM на хосте. Бывает, что DISM на хосте не может открыть смонтированный образ: ошибка 87, в `dism.log` строка «Failed trying to determine the OS Version», при этом `reg load` не загружает кусты. Так было на Windows Insider 26300. Тогда тесты можно прогнать в ВМ стенда:

```powershell
.\tools\bench\Invoke-Bench.ps1 -Iso D:\win11.iso -KeepVm   # ВМ с установленной Windows остаётся
.\tools\bench\Invoke-AdminTestsInVm.ps1 -VmName <имя ВМ из лога> -Iso D:\win11.iso
```

Скрипт публикует тесты самодостаточно (в ВМ нет .NET и сети), подключает к ВМ диск для данных на 120 ГБ, копирует тесты и ISO через PowerShell Direct и запускает тесты под пользователем сценария. Лог сохраняется в `<папка ВМ>\admin-tests.log`.

## Сценарий

Папка `scenarios\<имя>\`:

- `profile.json` — профиль без `source`/`output` (их подставляет стенд). Пути установщиков в `programs` — от папки сценария. Пользователь обязателен, пароль в режиме `store`: стенд входит под ним.
- `expect.json` — что проверить: `computerName`, `editionId`, `userLocale`, `keyboardLayouts` (KLID в порядке, первая — по умолчанию), `timeZone`, `userIsAdministrator`, `uiLanguage` (язык интерфейса пользователя), `uiLanguages` (языки интерфейса в системе), `apps` / `absentApps` (приложения пользователя — есть / нет), `files` (список `{ path, contains }` или `{ path, absent: true }`), `registry` (список `{ path, name, value }`; `path` в виде `HKLM:\…` или `HKCU:\…` — HKCU пользователя профиля, `name` = `(default)` для значения по умолчанию). Отсутствие TPM проверяется всегда. Новые проверки добавляются в `Invoke-Bench.ps1` (блок `switch`).

Сценарии: `full-unattended` — всё сразу (твики, пользователь, программы, обои); `servicing` — офлайн-обслуживание: источник — ISO, собранный в ВМ (`Invoke-BuildInVm.ps1` с профилем `"languages": { "add": ["en-US"] }` и `"dotNet35": true`); стенд делает en-US языком Windows и проверяет язык и .NET Framework 3.5; `uup` — образ из Windows Update со встроенными приложениями (собран в ВМ с `removeApps`), стенд проверяет приложения пользователя.
